<objective>
Close **WR-07** and **WR-04's popup hop**: make the failed-save path leave the agent with a truthful
control they can still use.

**As a** Zendesk support agent whose off switch just failed to save, **I want to** see the setting as
it actually stands and be able to try again, **so that** the panel is not telling me one thing while
the switch shows another.

Purpose: the `change` event has already moved `control.checked` to the desired value before the
request is sent. On the illegible-reply path `showPreference(null)` deliberately leaves `checked`
alone — but "where the agent last saw it" is the *new, unconfirmed* position, so the agent sees an
unchecked box next to "Zhroma could not save that setting". `control.disabled = true` then makes the
switch permanently inert for the life of the popup, and `end(hadFocus)` cannot restore focus because
it is guarded by `!control.disabled`, so a keyboard user is dropped into `body` with no recovery.
Separately, `ask()` has no timeout, so a worker that never answers never reaches that path at all.

Output: a last-confirmed value the control reverts to, an enabled control after a failure, focus
restored when it was taken, a bounded request, and four mutants proving each of those guards is
load-bearing.

Reference: `04-REVIEW.md` → WR-07 and WR-04.
</objective>

<scope_boundary>
`showPreference(null)` is reached from **two** places, and only one of them is WR-07.

- **The failed-save path** (`requestEnabled`, after a `change` the agent caused): this is WR-07.
  The control has already moved, so there is a wrong position on screen to correct, and `begin()`
  took focus away, so there is focus to restore. Fixed by Task 1.
- **The initial-refresh path** (`refresh()` on open, before any agent action): **out of scope, and
  deliberately unchanged.** Nothing has been confirmed, so no position may be displayed and no write
  may originate from an unknown baseline — the control correctly stays disabled with the
  non-committal connection copy. `begin()` was never called on this path, so no focus was taken and
  none needs restoring. `control.defaultChecked` is **not** an acceptable revert target here or
  anywhere: `popup.html` ships the checkbox unchecked, so reverting to it after a failed attempt to
  turn tinting *on* would display an unconfirmed *off*, which is the same defect in the other
  direction.

The single `lastConfirmed` variable introduced in Task 1 reconciles both paths: when it is still
`null` — no reply has ever delivered a boolean — the failed-save path keeps today's
disable-and-show-nothing behaviour, because there is genuinely no confirmed position to return to.
</scope_boundary>
