<objective>
Close **WR-01**: give the worker's staleness design an executable specification.

Purpose: the test named as this property's guardian —
`a slow earlier reply cannot repaint over a newer projection` — **cannot construct the hazard it
names.** The tracer's `replyDelays` is consumed as the `delay` argument of `deliver()`, which wraps
the *listener invocation* in a `setTimeout`, so the content script computes its reply *after* the DOM
change and answers with the status it holds at that moment — already the new one. There is no stale
payload in flight, so no guard is needed to make the assertion pass. The review proved the
consequence: with `generationOf(` reduced to zero call sites **and** the per-tab queue removed, all
277 behavioural tests still passed, and the only red test was the SHA-256 byte pin, which fires on any
edit whatsoever.

The failure this leaves unfenced — one tab's diagnosis painted onto another tab's toolbar, a positive
`working` surviving a navigation — is exactly what FAIL-05's `navigation-status` check exists to
catch. A refactor that drops the design lands silently, and dropping it is the single most likely
edit when the diagnosis taxonomy grows.

Output: three holds in the double that let a stale payload genuinely exist, a repaired guardian test,
one test per guarded site, and seven mutants that each must die.

Reference: `04-REVIEW.md` → WR-01, `## Required judgment 1` group A, and
`## Required judgment 2`'s closing note that the tripwire is half-armed.
</objective>

<the_six_guarded_sites>
The worker has six generation checks and one serialization point. This plan requires each to be
individually killed, because a mutant that only dies when *all* guards are removed proves nothing
about any single one.

| Site | What it guards | How the hazard is constructed |
|---|---|---|
| `requestStatus` catch branch | a late *rejection* must not paint a stale `unavailable` | silence the tab's listeners without marking it disconnected, with a delayed delivery, so the rejection lands after a newer invalidation |
| `requestStatus` post-await recheck | a late *successful reply* must not be returned to a superseded projection | hold the response payload |
| `project` recheck after `requestStatus` | a superseded status result must not proceed to the preference read | hold the response payload |
| `project` recheck after `readPreference` | a late preference read must not paint a superseded status | `setReadMode('deferred')` plus `flushReads` after a new invalidation |
| `applyAction` recheck between the two writes | a generation bump between `setIcon` and `setTitle` must stop the title write | hold the action so `setIcon` resolves late |
| `popupStatus` recheck | a superseded popup projection must report `unavailable`, not a stale diagnosis | hold the response payload |
| `project`'s `state.queue` chain | two projections must not run concurrently | two invalidations while the first response is held |

Four of the seven are constructible with capabilities that already exist; the other three need the
holds Task 1 adds. None requires a change to a shipped byte.
</the_six_guarded_sites>
