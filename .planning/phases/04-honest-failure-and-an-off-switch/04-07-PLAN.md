<objective>
Close **CR-01** and **WR-08**: make every English regional locale a supported shell instead of a
falsely-blamed one, and make the four tint declarations win the cascade the way this project's
`CLAUDE.md` prescribes.

**As a** Zendesk support agent on an `en-GB` agent interface, **I want to** see priority tinting and
an honest toolbar state, **so that** the extension does not silently do nothing while telling me my
own language is the problem.

Purpose: `content.js` compares `document.documentElement.lang` for exact case-sensitive equality with
`en`, and `zhroma.css` encodes the same predicate independently as an exact attribute match. Every
`en-US` / `en-GB` / `en-AU` / `en-CA` / `en-IN` / `EN` shell therefore takes the
`unsupported-language` branch and nothing paints — in the phase whose whole subject is honest
failure, and in exact mirror of what FAIL-03 and D-04 promise. Three test files currently lock that
behaviour in as intended.

Output: a language-family predicate in both encodings, a locale matrix that fails if the two
encodings ever disagree, the important flag on all four declarations, and the three lock-in tests
inverted so `en-US` is a positive case.

Reference: `04-REVIEW.md` → `## Critical Issues` → CR-01, and `## Warnings` → WR-08.
</objective>

<assumption_delta_decision>
The deterministic detector returned `detected: false` for this phase, so this block is recorded on
the planning brief's explicit instruction, not because the probe fired. It is advisory and blocks
nothing.

- **The noun that is now primary:** the **language family** (`en` and every `en-*` subtag), not the
  single tag `en`. CR-01 is a textbook singular-to-plural transition: one exact token becomes a set.
- **Decision: `promote`.** The family becomes the primary representation in both encodings, and the
  bare tag `en` is demoted to one member of it. It is *not* added alongside a still-required exact
  `en` match — an implementation that kept both would leave two predicates to drift apart, which is
  the defect being fixed.
- **Where the single source of truth lives:** it cannot be a shared *file*. This project ships no
  build step (D-06), and CSS cannot import a JavaScript constant, so the predicate is necessarily
  encoded twice. The single source of truth is therefore the **contract**, not the constant: the
  locale-matrix agreement test added in Task 3 is the one place where the accepted set is written
  down once and both encodings are checked against it. That test is what makes the duplication safe.
- **What would force a later promote to a shared constant:** a build step arriving (the `CLAUDE.md`
  v2 WXT migration). At that point the family belongs in one module consumed by both, and the matrix
  test becomes a regression guard rather than the contract.
</assumption_delta_decision>
